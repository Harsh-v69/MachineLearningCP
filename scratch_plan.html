Semester Project Roadmap

TAPE: Structural Graph Validation & Adaptive Solver Selection

A 16-week phase plan for extending TAPE (Tool-Guided Adaptive Planning with Constrained Execution) along the two directions its authors flag as open: plan-graph structural integrity and solver generalization.

Base paper: Jeong, Kim & Lee (2026), TAPE — arXiv:2602.19633v1

Phase Timeline

1
TAPE BaselineWeeks 1–4

Reproduce the core pipeline: candidate plan generation, merging into a plan graph, ILP/CP-SAT path selection, constrained-decoding execution, and mismatch-triggered replanning.

Gemini APINetworkXOR-ToolsSokoban · GSM8K-Hard
2
Adaptive Graph ValidationWeeks 5–6

Check candidate states/actions against environment rules, budgets and constraints before they enter the graph — reject invalid transitions, downweight uncertain ones.

Custom rule engineSokoban · ALFWorld
3
Self-Improving GraphWeeks 7–8

Log successful/failed transitions to an experience store; feed past outcomes back in as a confidence signal on later graphs.

PostgreSQLFAISS / Chroma
◆
Mid-Semester Review — ~60% completeWeek 8

Live demo of the full pipeline on 2 benchmarks: baseline TAPE run alongside the validated + experience-weighted graph. Report invalid-transition rate before/after validation, and confidence drift across repeated episodes.

4
Dynamic Reachability / Utility ScoreWeeks 9–10

Score each state on goal proximity, accumulated cost, remaining budget, constraint satisfaction and transition confidence — replacing a single fixed reward signal.

Custom scoring module
5
Adaptive Path SelectionWeeks 11–12

Use the utility score as an A*/AO* heuristic where feasibility is simple; keep ILP/CP-SAT for tasks with hard multi-constraint optimization. Select the method per task instead of fixing one solver globally.

A* / AO*OR-ToolsLangGraph
6
Evaluation & AblationsWeeks 13–14

Controlled comparison of baseline vs. proposed variants across all four benchmarks: success rate, planning error, invalid-transition rate, replanning frequency, planning time, execution cost.

SokobanALFWorldMuSiQueGSM8K-HardDocker
◆
End-Semester Review — Final DeliverableWeeks 15–16

Final report and presentation: full benchmark comparison table, ablation studies isolating each extension's contribution, and an explicit analysis of when the proposed extensions help and when the original solver-only approach still wins. Code repository handed off in a reproducible Docker environment.

Expected Outcomes

01Reproducible TAPE baseline for direct comparison.
02Validated plan graph with fewer invalid/inconsistent transitions.
03Feedback-based confidence mechanism from past executions.
04Dynamic state-scoring that adapts to task constraints.
05Adaptive path-selection layer choosing search vs. formal optimization per task.
06Clear analysis of where extensions win and where the original solver still wins.
*used only if semantic retrieval / graph-scale needs justify it — Phases 1–4 target ~60% of total project effort, delivered by the mid-sem checkpoint.
